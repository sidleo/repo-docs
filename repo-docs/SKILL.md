# 项目文档生成

先了解项目，再把**协作规则写进 AGENTS.md，项目说明写进 README.md**。默认同时生成两份；用户指定单个文件时，只改该文件。直接在目标项目落盘，有效的已有内容按需合并。

本 skill 只负责这两份文档的内容，不管理其他 Agent 的入口文件、软链接或环境配置。

本 skill 仅依赖文本阅读、搜索和文件写入能力；Git 可选。使用宿主现有工具，不依赖特定 Agent、联网服务、CLI 插件或本机绝对路径。

## 1. 确定目标与已有约束

- 用户指定的目录优先，否则使用当前项目目录。多仓库且目标无法判断时询问目标；同时继续不依赖该选择的工作。
- 遵守适用的环境与项目指令，读取现有 AGENTS.md、README.md 的内容。既有指令属于约束，不因生成文档而自动失效。
- 使用中文叙述和标题；文件名、代码标识、命令保留原文。若用户明确指定语言或标题，采用该要求。
- 对现有文件做有针对性的更新；保留仍有效的业务约定、人工维护章节、许可证及必要链接。已证实过时的事实可以修正。规则冲突无法判断时保留相关内容并询问，不因缺一处信息停止其他可完成部分。

## 2. 从项目取得依据

先看根目录和两至三层目录，再沿相关入口补读。只读取与文档有关的内容，跳过依赖目录、构建产物、缓存、大型数据和二进制文件。

| 要确认的事项 | 优先查看的依据 |
| --- | --- |
| 用途、使用者、已有功能与边界 | 现有说明、入口代码、命令帮助定义、示例、接口或任务配置 |
| 模块、测试、资源与生成目录 | 实际目录树、工作区配置、导入关系、版本控制忽略规则 |
| 安装、运行、构建和验证入口 | 依赖清单、锁文件、任务脚本、Makefile、CI 配置 |
| 风格和命名 | 格式化/lint 配置、编辑器配置、代表性源码与测试 |
| 配置项与外部依赖 | 配置定义、公开配置示例、启动代码、部署说明 |
| 提交与 PR 约定 | CONTRIBUTING、PR 模板、提交检查配置及最近约 20 条提交 |

搜索优先使用 `rg --files` / `rg`；不可用时使用宿主等效工具。Git 可用且目标位于仓库内时，可读 `git status --short`、`git log -20 --format=%s`；没有 Git 时继续检查文件。

把“已有明确规则”“从代码/历史观察到的习惯”“尚待确认的信息”分开处理：明确规则可直接写成要求；稳定习惯标为建议；证据不足则省略或简短注明现状。不能把少数提交概括为强制 Conventional Commits，也不能推断覆盖率门槛、许可证、部署地址或尚未实现的功能。

完成这一阶段时，应能为每条具体命令、目录、配置与约束指出来源。不必额外生成探查报告。

## 3. 编写两份文档

编写 AGENTS.md 时，读取 [协作规则写作规范](references/agents-guide.md)；编写 README.md 时，读取 [项目说明写作规范](references/readme-guide.md)。只加载本次需要的规范。

共同要求：

- 按实际项目选择章节，用简短段落、行动句和少量有效示例；删掉不适用章节与模板占位符。
- 目录和命令必须真实。缺少测试入口就写清现状与可行的现有验证方法；不为凑齐章节创建测试框架、脚本或源代码。
- 命令注明工作目录、用途与必要前提；多模块项目区分各模块入口。可少量重复关键验证命令，完整安装和使用步骤集中在 README.md。
- 项目名、入口、路径、配置项、验证方式在两份文档中保持一致，使用相对链接互相引用。
- 新项目只写已确认的目标与现有文件；明确区分计划与已实现内容。无法确定项目用途时提出一个关键问题，先完成已知部分。
- 正文仅保留持久信息；本次探查过程、生成时间、临时环境缺失和未决问题放交付说明，避免每次运行都产生无意义改动。

## 4. 验证并交付

逐项检查，修复能确认的问题：

- **分工**：AGENTS.md 中每项都能指导贡献者的行动；README.md 能让新读者理解项目并找到可用入口。
- **依据**：逐一对照命令定义、路径、配置和测试入口；只写实际存在的规则与能力，示例输入输出有来源或明确标为示意。
- **一致性**：检查两份文档的相对链接与 Markdown 代码围栏，确认相同项目事实的表述一致。
- **保留内容**：查看差异及所有新文件，确认已有有效规则、用户改动和人工章节得到保留；无变化时保持文件不变。Git 可用时可用 `git diff --check` 检查已跟踪文件的空白问题，新文件另行检查。
- **执行状态**：文档任务默认按源码/配置核对命令；按需运行无副作用的轻量检查。先检查脚本内容，不为验证文档擅自安装依赖、联网、启动长期服务、发布或迁移数据。交付时区分“已实际执行”和“依据配置确认、未执行”。
- **信息保护**：配置示例只展示变量名、非敏感默认值或占位值；不读取真实密钥文件来填充文档。内部权限规则按原约定放置，公开说明不扩散私密信息。

最后简短列出生成/更新的文件、主要调整、验证方式和仍需确认的事项。写权限不足时交付带文件名的完整内容，说明尚未落盘；不能声称文件已生成。
